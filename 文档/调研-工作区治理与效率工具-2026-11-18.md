## 一句话结论

**先定结构，再装 3 样工具**。缺的不是软件，是"东西该放哪"的规则；工具只能加速一个正确的结构。

最小三件套：**Everything**（止住找不到）+ **PowerToys · Command Palette**（统一入口）+ **Obsidian QuickAdd**（把规则变成一次按键）。

## 三、方法论与骨架

- **PARA** https://fortelabs.com/blog/para/ ：项目 / 领域 / 资源 / 归档
- **Johnny Decimal** https://johnnydecimal.com/ ：顶层数字前缀，排序稳定
- **GTD 收件箱**：允许乱，但只允许乱在一个地方

### 实际采用的骨架（跨盘版 PARA）

调研原方案是把所有东西塞进 `D:\AI`。实际按用户选择改成**跨盘分层**：

```
D:\AI\          资源层 —— 知识库\ 文档\ 脚本\ 工具\ _收件箱\ 归档\
D:\Projects\    项目层 —— 岗位雷达\ 标签生成器\ PeripheralBattery\ + 原有 8 个项目
D:\个人\        私人层 —— 私人\ private\
```

### 临时文件三层隔离

| 层 | 目录 | 规则 |
|---|---|---|
| 收件箱 | `D:\AI\_收件箱\` | 只放"还没决定去哪"的，每周清空 |
| 归档 | `D:\AI\归档\` | 冷数据，按日期分目录 |
| 产物 | 项目目录内 | 只放要交付的最终件 |

两条硬规则：
1. 文件名禁止用 `2` / `_out` / `_final` 表版本，用 git。
2. **改目录名必须同步改 `.gitignore`**——它是按目录名放行的白名单，改名会静默失效。
