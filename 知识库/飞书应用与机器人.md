# 飞书应用与机器人

这套经验来自 `D:\Projects\Feishu-Codex`（手机飞书里的 Codex 机器人）；以后每接一个 AI 工具都要走一遍，所以记下来。

## 建应用与控制台操作

开发者后台：`open.feishu.cn/app`。建自建应用要做四件事：

1. 添加应用能力 → **机器人**
2. 权限管理 → 勾选所需权限（见下）
3. 事件与回调 → 订阅方式选**使用长连接接收事件**（不需要公网域名），再加事件 `im.message.receive_v1`
4. 版本管理与发布 → 创建版本 → 可用范围只勾自己（≤6 人免审）→ 发布

机器人收发消息的最小权限组合：

| 权限 | 用途 |
|---|---|
| `im:message.p2p_msg:readonly` | 读用户发给机器人的单聊消息（配 `im.message.receive_v1`） |
| `im:message:send_as_bot` | 以应用身份发消息 |
| `cardkit:card:write` | **只在需要流式/卡片输出时才加**（缺它会返回 400，报 `cardkit:card:write` 相关错误） |

不要图省事加 `im:message`——那条含群消息读取，而机器人只处理私聊。

## 免审权限立即生效，不用发版本

控制台里标「免审权限」的 scope，点「确认开通权限」**当场生效**；
版本页里「权限变更」显示「暂无」也正常——它不需要随版本发布。
但**正在跑的进程里缓存的 tenant_access_token 还是旧的**，表现为继续报权限不足；
**重启进程**拿到新 token 就好了（这次就栽在这：先以为是缺版本发布，其实是缓存）。
另外注意应用 Secret 复制后要重启进程，SDK 的 token 有缓存。

## 流式输出（边生成边显示）

飞书 SDK：`channel.stream(chatId, { markdown: producer })`，producer 拿到 controller：

- `controller.append(chunk)` 追加
- `controller.setContent(full)` 覆盖（适合把「正在处理…」占位换成第一段真实内容）
- 结束时 producer 必须返回，否则卡片停在半截

前提是 **`cardkit:card:write`**；没有它直接 400。普通文本消息（`channel.send`）不需要这个权限。

## 一个会话同一时间只有一个写入者

协议层的硬约束：`thread/resume` 会回 `already has an active writer`。
**桌面端 Codex 会一直占着它加载过的会话**，所以从手机（另一个 app-server 实例）接不了手——
不是 bug，是模型。想在两边共用同一个会话，只能先在一边关掉它。
归档过的会话要先 `thread/unarchive` 再 `resume`（可以让程序自动做）。

**变通：`thread/fork` 复制一份。** 想「手机接着电脑端那个会话聊」，但又撞上写入者唯一时，
可以让手机侧 fork 出新会话（`thread/fork {threadId, cwd, model, sandbox, approvalPolicy, approvalsReviewer}`），
上下文带过去、两边之后各自独立。这样「电脑 + 手机同时用」就成立了——
代价是两边不再共享后续修改（本质上是两条分支），想要严格同步只能一边关掉。
