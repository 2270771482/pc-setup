# 系统与网络

> 2026-09-19 由原 4 个主题合并：Windows-账户与权限、Windows-文件与磁盘、开机与服务、网络与代理。只调整了标题层级，内容没删。

## Windows：账户与权限

### 会话里的命令跑在「沙箱账户」上，不是用户本人

- 现象：会话内（未提权）`whoami` 得到 `codexsandboxoffline`（SID 尾号 1003），提权后才是真实用户（尾号 1001）
- 后果：**HKCU 是两个不同的配置单元**，会话内读 HKCU 读到的是沙箱账户的默认值，会得出完全错误的结论
  （曾因此误判「文档/下载重定向被还原」，其实用户配置一直是好的）
- 对策：判断用户自己的配置（HKCU、Explorer/OneDrive、启动项、已装组件）**必须用提权命令**，
  或者看磁盘物证（desktop.ini、目录时间戳、文件所有者）
- 不受影响：HKLM、服务、文件系统——会话内读到的就是真实的

### 三种「身份」要分清

| 身份 | 怎么来 | 能做什么 | 不能做什么 |
|---|---|---|---|
| 沙箱内（默认） | 会话里的命令 | 读全盘、写 `D:\AI` 等工作区 | 读对 HKCU、写工作区外、**移动文件** |
| 提权（`require_escalated`） | 沙箱外、**同一用户身份** | 读写用户目录、装软件、联网 | 改服务、改 HKLM、删 Program Files |
| 真管理员（UAC） | `Start-Process -Verb RunAs`，用户点一下 | 改服务启动类型、删系统目录、动 HKLM | —（要用户点确认） |

**踩过的坑**：以为「提权」就等于管理员，直接跑 `Set-Service`/`Stop-Service`，被静默拒绝（白跑一次）。
需要管理员的活一律走 UAC 脚本。

### 会话里**能**发 UAC，但要提前告诉用户去点（2026-09-19 两次失败后才搞清）

先踩了坑：连着两次 `Start-Process powershell -Verb RunAs ...`，用户说屏幕上什么都没出现，
我一度以为"会话里发不起 UAC"（**这个结论是错的，别再传播**）。
第三次**逐秒轮询 `consent.exe` 才看清真相**：命令发出后第 4 秒 UAC 同意窗口确实弹了出来，
第 5 秒提权子进程就起来了 —— 前两次是**用户没注意到、超时自动取消**（UAC 默认约 2 分钟后自动消失）。

正确姿势：

1. **先跟用户说一声**："马上会弹 UAC，请点『是』"，再发命令；
2. 发完**轮询 `Get-Process consent`** 确认弹窗真的出现（别只看命令有没有报错——
   用户不点，`Start-Process` 不会抛错，只会静默超时）；
3. 提权子进程要**自己写结果文件**，我在外面读文件，别指望拿到它的 stdout。

其它要点：

- 日常账户 22707 **在 Administrators 组里**，但 Codex 的令牌是过滤后的，
  `IsInRole(Administrator)` 恒为 `False`；`Set-Service`、改 HKLM、
  `Microsoft-Windows-Diagnostics-Performance/Operational`（开机耗时日志）这类都读不到/改不动。
- 提权子进程的**命令行里别放中文路径**（会被编码搞坏）：用
  `Get-Item 'D:\AI\*\boot-time-report.ps1'` 这种通配符避开中文目录；
  输出也先写英文路径（如 `%TEMP%`），事后再由我搬回 `产物\logs\`。
- 备一条不依赖 UAC 的路：ASCII 内容的 `.cmd` 让用户**右键 → 以管理员身份运行**
  （实例 `工具\量开机耗时.cmd`），适合"用户本来就在电脑前"的场景。

### 沙箱内不能移动/重命名文件

实测：沙箱身份可以创建、修改、删除 `D:\AI` 里的文件，但 `Move-Item` 会静默失败。
批量搬文件（归档、重组目录）要用提权执行。

### 凭据排查与脱敏（改名前备份的坑）

改目录名、清理文档之后，**旧备份里往往还留着明文**——备份是压缩包，扫文档时不会被发现。

- **扫描**：按扩展名（`.md/.txt/.json/.ps1/.py/.toml/.ini/.log`…）加体积上限遍历，
  正则找 `sk-[A-Za-z0-9]{20,}`、订阅域名、`ANTHROPIC_AUTH_TOKEN`、`OPENAI_API_KEY`、
  `BEGIN OPENSSH PRIVATE KEY`；压缩包要先解开再扫。
  **只输出文件名和命中次数，绝不打印命中的原文**（一打印就进了会话记录）。
- **脱敏**：压缩包里的条目用「读文本 → 正则换成 `[REDACTED-*]` → 删条目再用同名写回」原地重写，
  比删掉整个备份合适（历史留下，秘密不在）；改完必须复扫确认。
- **坑**：`Add-Type -AssemblyName System.IO.Compression.FileSystem` 只提供 `ZipFile`，
  要用 `ZipArchiveMode` 还得另外加载 `System.IO.Compression`，否则报「找不到类型」。
- 脱敏只处理文件，**已经流出去的值只能靠轮换作废**——所以顺序是「先脱敏、再轮换」。

## Windows：文件与磁盘

### AF_UNIX socket 文件会「僵死」

- 现象：`*.sock` / `engine.sock` 这类文件删不掉也改不了名，报「系统无法访问此文件」（`File.Delete`、`del`、`Rename-Item` 全失败）
- 关键发现：**同样操作在 D 盘完全正常，在 C 盘的某些目录会僵死**；优雅停止和重启系统都清不掉
- 判断：这是 reparse point 层面的问题，不是权限问题（权限问题会报"拒绝访问"）
- 绕法：把**整个目录**改名挪走（目录级重命名可以成功），让程序重建一个新目录
- 受害者实例：Docker Desktop（见 `软件.md` 的 Docker 一节）

### 删大量小文件：robocopy 镜像法

`takeown` + `icacls` + `Remove-Item` 删 `C:\Windows.old`（9 万多个文件）会卡十几分钟还删不干净。
改用「robocopy 空目录 /MIR 镜像过去 + `rd /s /q`」几秒搞定：

```powershell
robocopy "C:\空目录" "目标目录" /MIR /NFL /NDL /NJH /NJS /NP /R:1 /W:1
rd /s /q "目标目录"
```

### 权限/所有权

- `takeown /f <路径> /r /d y` 拿所有权，`icacls <路径> /grant *S-1-5-32-544:F /t /c /q` 授权
- **`icacls` 授权用 SID 写**（`*S-1-5-32-544` 是 Administrators），中文系统下写英文组名会失败

### 删数据前先打包

删任何数据目录（数据库、旧配置）之前先压一份到 `D:\Backups`，确认存在再删。
删库不可逆，一份几十 MB 的保险成本可以忽略。实例：PostgreSQL 旧数据目录。

### 已知文件夹（文档/下载）重定向

- 用 `SHSetKnownFolderPath` + 注册表双保险：`HKCU\...\Explorer\User Shell Folders` 为准，
  `Shell Folders` 是解析后的副本（存在才更新，别创建半个）
- 验证方法：`SHGetKnownFolderPath` 回读，或看目标目录里有没有 `desktop.ini`
- 脚本：`脚本\restore-known-folders.ps1`（可重复执行）
- 会被谁改回去：OneDrive 打开「备份文件夹」时

## 开机与服务

### 开机时间怎么量

看开机性能事件（系统日志里的开机性能记录），别凭感觉。实例基线：
09-17 那次 49.8 秒、09-18 那次 58.6 秒，其中 post-boot（登录后拉起程序）占 14～37 秒。
**结论：拖慢开机的通常不是系统本身，而是登录后自动拉起的一堆程序。**

### 关服务的判断标准

可以关（改成「手动」或「禁用」）：

- **遥测/诊断上报**：DiagTrack、Killer Analytics、各类 Analytics（直接禁用）
- **厂商支持工具**：Dell Data Vault 三个、Digital Delivery、Hardware Support、SupportAssist 系列
- **按需启动类**：打印机后台（Spooler，用到时会自动起）、ClickToRun 更新器、LGHUB 更新器、
  错误报告（PcaSvc）、卷影复制维护（TrkWks）、地图（MapsBroker）等

不要碰（会影响功能）：风扇/性能档控制（AWCC）、Intel 动态调优（esifsvc/jhi_service）、
文件搜索（WSearch）、SysMain、显卡容器、音频服务、WSLService、数据库服务。

改不动的：受系统保护的服务（如传递优化 DoSvc），`Set-Service` 报拒绝访问，就随它去。

### 服务改「手动」比「禁用」安全

需要时能自动/手动起来，平时不占开机。实例：MySQL 与 PostgreSQL 都改成手动，
要用时跑 `工具\启动数据库.cmd`。

### 自启动项

分两处看：`HKCU\...\CurrentVersion\Run`（用户级）和任务管理器里的启动项。
实测可以去掉的：Edge 预启动（`MicrosoftEdgeAutoLaunch_*`）、OneDrive 后台自启。
**读 HKCU 必须提权**（见本文档「Windows：账户与权限」一节）。

### 自启动一共有六处，别只盯 Run 键（2026-09-19 全盘扫过一遍）

1. `HKCU/HKLM ...\CurrentVersion\Run`（+ `RunOnce`、`WOW6432Node` 的 Run）
2. 启动文件夹：`%APPDATA%\...\Start Menu\Programs\Startup` 和 `%ProgramData%\...\StartUp`
3. `HKCU\...\Explorer\StartupApproved\Run`：任务管理器里的启用/禁用状态
   （**删了 Run 值但这里还留着，就是一条看不见的孤儿记录，顺手清掉**）
4. 计划任务：筛 `Triggers` 里带 `Logon`/`Boot` 的，**排除 `\Microsoft\*`** 那几百条系统自带的
5. 商店（UWP）应用自启：`HKCU\Software\Classes\Local Settings\...\AppModel\SystemAppData\<应用>\<X>StartupTask`
   的 `State`（**2=启用，1=禁用**）。实例：Dell Mobile Connect 就藏在这里，Run 键里根本看不到
6. 自动服务：`Get-CimInstance Win32_Service` 里 `StartMode='Auto'`，滤掉 `svchost` 那些系统组件

**"关了又回来"的两个真凶**：① 计划任务（OneDrive 就是这样爬起来的）；
② 应用自己的"开机启动"开关会重新写回 Run 键。所以关完要**回头复查一遍**，别只看当时生效。

**权限**：Run 键和商店自启在用户级，普通提权就能改；
**WPS 那种系统级注册的计划任务，用户身份下 `Disable-ScheduledTask` 报"拒绝访问"，必须真管理员**（走 UAC）。

### 改动前先留回滚

把每个服务原来的启动类型导出成 JSON 存到 `D:\Backups\<批次>\`，配一个回滚脚本。
实例：开机优化那批的原始值在 `D:\Backups\boot-optimize-20260918\`，
回滚脚本 `脚本\archive\revert-boot-optimize.ps1`（一次性脚本，已归档）。

### 不是每次开机都有记录（快速启动的坑）

开机耗时只记在 `Microsoft-Windows-Diagnostics-Performance/Operational` 的 **EventID 100**，
而且**不是每次开机都写**：`HiberbootEnabled=1`（快速启动）时，"关机再开机"本质是恢复休眠，
**不留性能记录**。实例：2026-09-18 18:28 那次引导就没有记录（日志里只有一条
`BL_LOG_ERROR_RES_HARDWARE_SIGNATURE_MISMATCH`，宿主机硬件变了导致休眠恢复失败）。

**要拿到记录，让用户走「重启」**——重启永远是完整冷启动，会写 EventID 100。

怎么量：右键 `工具\量开机耗时.cmd` → 以管理员身份运行（**这个日志只有管理员能读**），
报告落在 `产物\logs\boot-time-<日期>.txt`；读日志的脚本是 `脚本\boot-time-report.ps1`。

### 实测数据（2026-09-19 读到的全部 5 次）

| 时间 | 总 | 内核/驱动 | 登录后 |
|---|---|---|---|
| 09-17 17:23 | 293s | 273.7s | 19.3s |（重装系统后第一次）
| 09-17 17:30 | 36.6s | 12.4s | 24.2s |
| 09-17 21:05 | 49.8s | 35s | 14.8s |
| 09-18 07:29 | 58.6s | 21.7s | 36.9s |（优化前）
| **09-18 14:26** | **45.9s** | **15.4s** | **30.5s** |（优化后，唯一一次优化后样本）

**结论**：优化后 45.9 秒 vs 优化前 58.6 秒，两个阶段各快约 6 秒。样本只有一次，
波动本来就大（同一天早上还是 58.6），别把 -22% 当准数，但方向是对的。

**耗时大头是"登录后"（30 秒）**，其中单点最大的是 **`MsMpEng.exe` 29 秒**（Defender 首次扫描），
其次 `svchost` 7.8s、`dwm` 5.0s、`explorer` 3.1s。想再快，方向是**减少登录后自启**，
而不是继续关系统服务。

## 网络与代理

### Clash Verge

- 程序：`C:\Program Files\Clash Verge`（`clash-verge.exe` + 内核 `verge-mihomo.exe`）
- 配置：`%APPDATA%\io.github.clash-verge-rev.clash-verge-rev\`（`verge.yaml` 是界面设置，
  `clash-verge.yaml` 是运行配置，`logs\` 是日志）
- 混合端口 7897；`enable_system_proxy` 开系统代理；`enable_tun_mode` 是 TUN
- **读这些配置必须提权**，否则读到的是沙箱账户的空目录（见本文档「Windows：账户与权限」一节）

### 判断一个服务是不是"暴露在局域网"

三件事一起看，缺一不可：

1. 监听地址：`Get-NetTCPConnection -LocalPort <端口> -State Listen`——是 `127.0.0.1`（只本机）
   还是 `0.0.0.0` / `::`（所有接口）
2. 防火墙：有没有放行该端口的入站规则（`Get-NetFirewallRule` 里搜软件名）；
   没有规则 + 入站默认阻止 = 外面连不进来
3. 当前网络类型：`Get-NetConnectionProfile` 看是「公用」还是「专用」（公用更严格）

实例：MySQL 监听所有接口、root 无密码。**不要把「防火墙正好没放行」当成空密码的补偿**——
网络类型、防火墙规则和监听地址都会变，数据库一启动风险就回来了。
正确做法：设口令 + 绑定 `127.0.0.1` + 平时手动启动（见 `任务.md` 里的 T-20260918-14）。

### 测网络：直连和走代理要分开测

```powershell
curl.exe -s -o NUL -w "%{http_code} %{time_total}s" --noproxy "*" --max-time 8 https://目标
curl.exe -s -o NUL -w "%{http_code} %{time_total}s" -x http://127.0.0.1:7897 --max-time 10 https://目标
```

（沙箱内不能联网，带了 `--noproxy` 也会失败，网络测试要用提权执行。）

### 排查结论怎么写

别只说"网络没问题"，要给出：直连结果、走代理结果、DNS 解析、hosts 是否有自定义行。
这样才能排除掉"看起来像网络问题、其实是软件自己问题"的情况（WeGame 那次就是）。
