# 软件安装与卸载

## 优先用 winget，而不是逐个跑官网安装包

- 官网的下载按钮常常是 JS 生成的，抓不到直链（WeGame、网易邮箱大师都踩过）
- winget 有就用 winget；商店独有就加 `--source msstore`。已用过的 ID：
  `NetEase.MailMaster`（winget 源）、`XP8LZ3XFW0JQLZ`（WeGame，msstore 源）、`CrystalDewWorld.CrystalDiskInfo`
- 静默安装参数：`--accept-package-agreements --accept-source-agreements --disable-interactivity`
- 支持自定义目录的包可以传 `--location`

## 批量安装：一个提权脚本装全部

每个需要管理员的安装都会弹 UAC。做法：把整批安装写成一个脚本，
用 `Start-Process -Verb RunAs` 启动一次，**用户只点一次 UAC**，之后全部自动装完。

注意：这个脚本必须只写 ASCII（见 `PowerShell.md`）。

## 卸载残留：服务 + 目录 + 注册表三处一起清

有些软件（OEM 预装尤其）没有卸载入口，注册表里也查不到卸载项。清法：

1. `Stop-Service` → `sc.exe delete "<服务名>"`
2. 删 `C:\Program Files\<厂商>`、`C:\Program Files (x86)\<厂商>`、`C:\ProgramData\<厂商>`
3. 删注册表 `HKLM\SOFTWARE\<厂商>` 与 `HKLM\SOFTWARE\WOW6432Node\<厂商>`
4. 浏览器扩展目录也顺手查一下（Edge/Chrome 的 `Extensions`）

实测 McAfee WebAdvisor 用这套清干净了。注意残留的注册表壳可能删不掉（需要管理员 + 键的所有权），
但纯注册表壳无害。

## 装完要确认两件事

1. 程序本体在 C 盘（重装系统后能装回来），数据/库/缓存指向 D 盘
2. 在 `状态.md` 记一行（装了什么、版本、数据目录在哪）

## 商店版 vs 官网版

微软商店版（MSIX）由系统托管，不能写自己的安装目录，某些功能（网络加速组件等）可能受限。
官网 exe 版更"自由"。如果商店版行为异常，先考虑换成官网版。

## 卸载 Office 类软件前先找"用户自己产生的文件"

2026-09-19 卸 Office 2019 时固定下来的检查顺序：

1. 有没有自定义模板 / 词典 / 启动项：`%APPDATA%\Microsoft\Templates`、`UProof`、`Word\STARTUP`、`Excel\XLSTART`
2. **`D:\Documents`（以及用户常用目录）里有没有 Office 文档**——有就先问用户
3. 替代软件装好了没（本例 WPS 已装）
4. 授权信息：`cscript //nologo "C:\Program Files\Microsoft Office\Office16\ospp.vbs" /dstatus`（**要管理员**），
   输出存到 `D:\Backups\<批次>\`（**存档不进任何 Git 仓库**）

## 卸 Office 的 ClickToRun：进程不退出 ≠ 没卸掉

`OfficeClickToRun.exe scenario=install scenariosubtype=ARP sourcetype=None productstoremove=<产品码> ...`
用 `Start-Process -Wait` 等，会**长时间不返回**（提权脚本日志卡住、PowerShell 进程随后消失），
但实际卸载往往已经成功。**判定看结果**：ARP 里匹配不到 Office、`C:\Program Files\Microsoft Office` 消失、
开始菜单项消失、C 盘空间回升。同一脚本排在它后面的步骤会因为卡住而没执行，要单独补做。

## 文件关联：卸载后先看是不是已经有人接管

不用急着手工设默认程序，查两处就知道：

- 用户明确选择（优先级最高）：
  `Get-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\Explorer\FileExts\.docx\UserChoice" | Select ProgId`
- 这个 ProgId 指向的程序真的存在吗（避免留下失效记录）：
  `(Get-ItemProperty "Registry::HKEY_CLASSES_ROOT\<ProgId>\shell\open\command").'(default)'`

实测：卸掉 Office 后 `.docx/.doc/.xlsx/.xls/.csv/.pptx/.ppt/.pdf` **已自动由 WPS 接管**，
`shell\open\command` 指向的 `wps.exe` 也真实存在，不需要再动手。
