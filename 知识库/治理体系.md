# 治理体系：怎么做（AGENTS.md 的操作版）

`AGENTS.md` 只写规则与红线；这里写具体怎么落地。两边冲突时以 `AGENTS.md` 为准。

## 任务文件怎么建

位置 `D:\AI\任务\T-<日期>-<序号>-<短名>.md`，一项任务一个文件，文件名以稳定 ID 开头：

```md
# 给两个数据库设口令并只允许本机连接

- ID：T-20260918-14
- 状态：等用户        # 只用 待处理 / 等用户 / 阻塞 / 长期
- 优先级：P1          # P1 最急，P3 最不急
- 顺序：15            # 越小排越前，用来定总览里的次序
- 最后更新：2026-09-18 12:06
- 完成标准：写成「做完是什么样」，可验证
- 下一步：一句话，谁做、做什么（等用户的要写默认方案）
```

状态里**没有**「进行中」——进行中由认领卡表示。

## 认领卡（锁）

- 位置 `D:\AI\进行中\<任务ID>.md`，**原子创建**：两个会话同时建同名文件，只有一个能成功。
- 卡里四行够用：任务 ID / 会话标识 / 开始时间 / 涉及范围 / 状态。
- 建成功 = 认领到手；建失败说明别人在做，换个活。
- 卡是「正在工作」的标记，**不能拿来占着等人**：等用户时把任务状态改成 `等用户` 并删掉卡。
- `进行中\README.md` 有过期处理规则：超过 24 小时的卡只列出来问用户，不自动删。

## 两个必跑的命令

```powershell
python D:\AI\脚本\生成任务清单.py    # 任务文件/认领卡变了就重新生成总览
python D:\AI\脚本\体检.py            # 只读体检：行数、任务一致性、敏感串、备份新鲜度
```

`任务清单.md` 是生成物，**不要手改**；`工具\体检.cmd` 是给用户双击的入口。

## 状态锁怎么写

1. 原子创建 `进行中\共享-状态.md`，写上会话标识、开始时间、目的。
2. 改 `状态.md`（只写「现在」，不写流水账）。
3. 立刻删除锁。

锁已存在时：把待合并的结果写进自己的认领卡，稍后并入；`决策记录\` 追加前重读文件尾，避免重复。

## 任务从哪来 / 谁决定做什么

- **对话与任务不是一对一**：一个对话可能产生多个任务，一个任务也可能跨多次对话。
- 用户提的事、对话里发现的新问题 → **先落任务文件再动手**，不要做完才补记。
- 判断标准：**要改机器状态**（服务、设置、安装卸载、目录结构、数据）就登记；
  只读查询、问答、讨论、以及改治理文件本身，不用登记。
- 清单里的任务**先由用户挑**；他说「你看着办」时才由会话自己排序。
- **维护性杂活**（归类、整理、清理过期物、归档脚本、更新索引）会话自己做，不用问。

## 收工清单

1. 删自己的任务文件和认领卡（没做完就更新状态、最后更新、下一步）。
2. 跑 `生成任务清单.py`；做完的任务不留在总览。
3. 取状态锁，把新现状写进 `状态.md`，释放锁。
4. 有值得留住的理由 → 追加 `决策记录\<当月>.md`；踩过的坑 → 写进 `知识库\`。
5. 改过 `状态.md` / `决策记录\` / `任务\` 的话，跑一次 `脚本\发布私有仓.py`，
   把私密部分同步到私有仓 `pc-setup-private`（没变化时它什么都不做，放心跑）。

## 用户说「不做 / 取消」时怎么办（防止同一件事反复冒出来）

四步要一次做完，缺一步它就会再回来（2026-09-18 的「D 盘备份方案」就是这么反复出现的）：

1. **删掉任务文件**（`任务\T-*.md`）——留着的话，下次生成总览还会列出来；
2. **在 `状态.md` 的「已取消 / 已放弃」写一行**：日期、范围（是「两条都不做」还是「先不做」）、理由，
   并写明风险由用户自留，免得下个会话又替他操心；
3. **追加 `决策记录\<当月>.md`**：为什么取消、推翻了哪条旧结论；
4. **立刻跑 `脚本\生成任务清单.py`**——总览是生成物，不重跑就一直挂着旧内容。

两条反向纪律：

- **补建任务前先查**：看到 `状态.md` 引用某任务但文件不在，先去「已取消」段和决策记录确认它不是被否决过的；
  确认是新事情再补建。
- **别在 `状态.md` 里留悬空引用**：指向任务的编号必须对应现存任务文件；已取消的只在「已取消」段里提。
  `工具\体检.cmd` 会检查这两条（「已否决却还有任务文件」和「悬空引用」）。

## 编辑文件的两个保命习惯（踩过）

- **改治理文件前先读一遍**（尤其 `进行中\README.md`、`任务清单.md` 这类"说明+生成物"混在一起的文件）；
- **补丁里别写"空内容的 Add File"**：有一次手滑多写了一个 `*** Add File: 进行中/README.md` 却不带内容，
  结果**把已有的 README 清成 0 字节**。新增文件一定带内容；只想加一行就用 Update File 定点追加。
  真被清空了：`进行中\README.md` 的内容跟 `任务\README.md` 是一套口径，照它重写即可（10 分钟就能补回来）。

## 体积控制的判断标准

- `状态.md` 超过 120 行就压实：合并重复项、删过程细节，只留结论和还在生效的事。
- **可以压缩**：「已取消 / 已放弃」「已知问题」里已经变成背景的内容。
- **不许压掉**：机器与系统、硬盘健康、软件与开发环境、目录与数据这些「现状」。
- `决策记录\` 只追加、不删；控制手段是「每条写得短」。

## 保留期（只提示，不自动删）

| 地方 | 到期后怎么办 |
|---|---|
| `进行中\` | 超 24 小时没动：体检列出 + 下次开工问用户「还在做吗」；旧机制迁移卡例外（信息转存后可清） |
| `产物\logs\` | 超 30 天：列出问要不要清（结论先抄进知识库） |
| `收件箱\` | 超 30 天没收拾：列出问怎么处理 |
| `文档\` | 超 90 天没动：提醒一句「还要不要留」 |

## 公开与私有的现状

- Git 的公开/私有结构**还没定**，在定下来之前不要初始化、提交或发布仓库（任务 T-20260918-03）。
- 将来建仓时的默认思路：公开仓走**白名单**，只放 `AGENTS.md`、`README.md`、`安装规划.md`、
  `脚本\`、`工具\`、`知识库\` 与非敏感的 `文档\`；`状态.md`、`决策记录\`、`文档\重装清单.md`、
  密码库、含账号地址的资料走 `private\` 或不进仓。
- 体检脚本目前只看文件名和未提交改动——**敏感文件一旦提交且工作区干净就不会报警**，
  所以建仓时必须配「提交前扫描」，不能指望事后体检。
- `~\.codex\sessions`（对话记录）不进 Git；用户已决定不做专门备份，不重复催办。

## 目录职责表（哪个目录放什么）

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `决策记录\<年-月>.md` | 真决策（为什么这么定），只追加 | 经验、临时安排 |
| `知识库\` | 经验教训、「怎么做」，一主题一文件，可改写合并 | 一次性操作记录 |
| `任务\` | 一项任务一个文件，是待办事实源 | 已完成历史、过程日志 |
| `进行中\` | 同 ID 认领卡与 `共享-状态.md` 短锁 | 长期存放的东西 |
| `文档\` | 报告、说明、清单——写给人看、长期要读的 | 过程日志、临时材料 |
| `提示词\` | 提示词与素材（输入） | 生成结果 |
| `产物\` | 生成的文件、下载的产物（输出） | 手写的文档 |
| `脚本\` | 脚本本体（一次性的放 `脚本\archive\`） | 给用户双击的入口 |
| `工具\` | 能直接双击跑的入口 + `工具箱.md` 索引 | 脚本源码 |
| `收件箱\` | 一时归不了类的：先扔进来，别纠结 | 长期不整理的堆积 |

治理文件留在 `D:\AI` 根目录：`AGENTS.md`、`状态.md`、`任务清单.md`、`项目登记表.md`、
`安装规划.md`、`决策记录.md`（索引）；根目录允许放指向外部目录的快捷方式（如
`项目目录（D-Projects）.lnk`）。不属于主管理的东西：个人文件 → `D:\Documents`、
项目 → `D:\Projects\<项目>\`、备份 → `D:\Backups`。
