# 治理体系：怎么做（AGENTS.md 的操作版）

`AGENTS.md` 只写规则与红线；这里写具体怎么落地。两边冲突时以 `AGENTS.md` 为准。

> **2026-09-19 大简化（B 档）**：砍掉了 `任务\` 逐任务文件、`进行中\` 认领卡、
> `生成任务清单.py`、`体检.py`、`状态.md` 的锁，以及公开仓。任务只剩 `任务.md` 一个文件。

## 任务怎么写（`任务.md`）

一个表格，一行一个任务：ID / 任务 / 状态 / 最后更新 / 下一步。

- 状态只有三个：**等你** / **在做** / **长期**（长期 = 不主动提，等指标越界或用户提起）
- ID 格式 `T-<日期>-<序号>`，只为了对话里能指名道姓
- 做完**直接删行**；等用户不动的留在表里，并在"下一步"写清等什么、为什么卡着
- 任务需要用户先选定方案的，在"下一步"里写明**选定之前不许动手**（见 `AGENTS.md` 里那条）

## 收工清单

1. `任务.md`：做完删行；没做完更新状态与下一步
2. `状态.md`：把「现在」改成最新（**已经不需要锁了**，写完就走）
3. 有值得留住的取舍 → 追加 `决策记录\<当月>.md`；踩过的坑 → 写进 `知识库\<主题>.md`
4. 改过 `状态.md` / `决策记录\` / `任务.md` → 跑 `python D:\AI\脚本\发布私有仓.py`

## 用户说「不做 / 取消」时（防止同一件事反复冒出来）

删掉 `任务.md` 里那一行 → `状态.md` 的「已取消 / 已放弃」记一行（带日期与理由）→ 追加决策记录。

反过来：看到 `状态.md` 或别的文件引用某件事，而 `任务.md` 里没有时，
**先查「已取消 / 已放弃」段和决策记录**，确认不是用户否决过，再考虑要不要做。
（踩过：一份被用户否决过的清单反复被当成待办提出来，用户很不满。）

## 编辑文件的保命习惯（踩过）

- 用 `apply_patch` 时**别写不带内容的 `*** Add File`**——会把同名已有文件清空
- `AGENTS.md` 有时被 Codex 应用占用，`apply_patch` 删不掉，改用命令删再立刻写回
- 大删除、批量搬文件之前先确认能不能恢复（`git status`、有没有备份）

## 项目：只继承两样

主管理给项目的是 **红线 + 接手入口**，其余按项目自己的规范：

- **写代码的项目**：README、ADR（`docs\adr\`）、CHANGELOG、CI、测试——**不要**照搬主管理这套流程；
  单人单会话不需要认领卡
- 项目要有一个**冷启动入口**：项目 `状态.md`，或 README 里固定一节写"现在做到哪、下一步"
- 项目 `AGENTS.md` 第一行必须是「先读 `D:\AI\AGENTS.md`」
- 新建项目：建目录 + 约定文件 → 在 `项目登记表.md` 加一行（名字 / 路径 / 一句话说明 / 公开还是私有）
